# Skill Agent 文档总览

本文档集描述的是 2026-07-16 仓库中的实际实现，而不是历史设计稿。

## 项目定位

Skill Agent 是一个以 `Skill` 为中心的多 Agent 编排项目。

- `ManagerAgent` 负责意图识别、技能选择、工具规划
- `LearningAgent` 负责执行工具任务和 DAG
- `OrchestratorAgent` 负责整合结果并生成最终回复
- `SkillTrainer` 负责把用户显式教学沉淀为技能文件

系统同时提供三种入口：

- FastAPI REST + WebSocket PubSub
- Vue 3 前端
- CLI / Streamlit 同步入口

## 当前实现状态

**主执行链路（M0 完成）**

- 每次 `Agent.handle()` 生成唯一 `execution_id`，避免失败记录互相覆盖
- 工具执行记录真实名称/retry/fallback/latency_ms
- 主执行入口统一到异步 `Agent.handle()`

**技能系统（M1 完成）**

- `TeachingSession` 多轮教学状态机持久化（Collecting→Draft→Active）
- 技能版本不可变，同名多版本并存，`name@version.yaml` 不可原地覆盖
- `active` 指针显式激活版本，`match()` 只返回 active 版本
- Skill 验证流水线（DAG 无环/工具存在/schema/样例）
- 重复技能决策：reuse / update_new / cancel
- SkillManager 接入主链，支持 MANAGER 意图（列出/版本/回滚）

**身份与安全（本地单用户）**

- **没有鉴权**：无令牌、无登录、无用户表。`require_auth` 是 no-op 装饰器
- WebSocket 的 `client_id` 由服务端签发，只作为路由句柄；`session_id` 由客户端带回以恢复会话
- 多用户维度（`user_id` / `tenant_id` / 假用户服务 / `/api/users`）已全部移除
- 保留的是**多智能体维度**：`agent_id`、工具归属 `owner_agent_id`、按 `session_id` 的执行目录

**ToolHub 启动可观测性（M0-06 完成）**

- `ToolHub` 维护每个源的状态机：registered / connecting / connected / connect_failed / disconnected
- `GET /api/health` 暴露 `tool_sources` 聚合 + `sources` 详情;失败时顶层 status 降级为 `degraded`
- `connect_all()` 单源失败不影响其他源，失败状态被显式记录

**源码编码统一（M0-05 完成）**

- 所有源码统一 UTF-8（无 BOM、LF 换行、所有 `open`/`read_text`/`write_text` 显式 `encoding="utf-8"`）
- `infra/logger` 用 `_Utf8Stream` 包装 stdout，避免 Windows cp936/cp932 下中文日志乱码
- `core/memory_db` metadata / tags 写入使用 `ensure_ascii=False`，sqlite 列里直接是原生中文而不是 `\uXXXX` 转义
- JSON-RPC 走 stdio 的 MCP 链路保留 ASCII 兼容（`ensure_ascii` 默认）

**教学 e2e 闭环（M1-10 完成）**

- `tests/e2e/` 提供隔离运行时夹具 + ScriptedLLMProvider
- 4 个 e2e 用例覆盖 Teach → Confirm → Persist → Restart → Recall → Execute 全链路
- 完全离线运行，不依赖 OPENAI_API_KEY

**测试基线**

- `pytest -q` 通过（288 个测试，无 skip）
- 新增 `test_m0_identity.py` 覆盖 M0-01/M0-02 核心逻辑
- 新增 `test_m0_06_tool_hub_observability.py` 覆盖 ToolHub 状态机 + /api/health
- 新增 `test_m0_05_source_encoding.py` 覆盖 UTF-8 日志流 + 中文 sqlite 元数据
- 新增 `tests/test_c01_auth.py` 覆盖管理接口鉴权
- 新增 `tests/test_c01_session_identity.py` 覆盖服务端签发身份 + 会话令牌
- 新增 `tests/test_m3_04_skill_versioning.py` 覆盖技能版本演进与精确文件匹配
- 新增 `tests/test_m3_result_validator.py` 覆盖结果校验、回归样例与自动发布收紧
- 新增 `tests/e2e/test_m1_10_teaching_recall_e2e.py` 覆盖 M1-10 教学闭环
- 测试不依赖真实 `OPENAI_API_KEY`：`tests/conftest.py` 在缺少 key 时注入占位值

知识库子系统已拆为**独立仓库** `../onto_kb`（同目录平级），本仓库不再包含其代码与设计文档。

| 原文档 | 现在在哪 | 为什么迁走 |

| `21-知识库与动态本体方案` | `onto_kb/docs/` | 讲知识库自己怎么分层、分几期 |

**为什么拆**：变化节奏不同（本体建模改一次要想清楚，agent 编排改得频繁），
出错表现也不同（数据错了系统照常跑，编排错了立刻可见）。混在一起时，
改一次建模要重启整个 agent 才能验证。拆开后 `python -m kb.cli demo` 三秒跑完一轮。

依赖方向单向：本仓库调用 `onto_kb`，**`onto_kb` 禁止反向 import 本仓库**
（由 `onto_kb/tests/test_isolation.py` 用 AST 守着）。

`24` 留在本仓库，因为它讲的是 **agent 侧**怎么接（`ToolHub` / `manager` /
`subagents` / `critic`），跨仓库引用 `onto_kb` 的文档时以「§」标注。

## 当前已知限制

- **Session 进程内存** — `backend/session.py` 仍是进程内实现，服务重启丢失（M1-10 后待 M2 解决）；
  但**对话内容本身不丢**，已落库并可恢复
- **记忆分层已接入主链** — 短期记忆（会话内容全量保留）与长期记忆（用户画像）两条链都通了：
  画像由 **LLM 抽取 + 证据校验**写入、每轮常驻注入（**进 system prompt，回答生成侧也吃**）、
  可「忘掉」并同步清索引（本地单用户，没有 `user_id` 维度）
  （详见 [13-记忆分层与RAG方案.md](./13-记忆分层与RAG方案.md)）
- **长期记忆面板已做** — 「记忆」tab（`MemoryPanel.vue`）：列出、按类型筛选、逐条忘掉、全部忘掉、显示正在注入的内容
- **统一存储层（Repository 协议）未做** — `MemoryStore`(JSON) 与 `MemoryDB`(SQLite) 仍是两套
- **意图识别的 L3 澄清层已落地** — L0 守卫层、L1 闭集判别（6 标签 + 置信度）、
  L2 规划、L3 澄清（问一句 + 候选项）全部就位，LLM 层不再返回自由文本意图；
  评估集与混淆矩阵 nightly 也已就位（详见 [12-意图分层识别方案.md](./12-意图分层识别方案.md)）
- **用户纠正信号已接通** — 隐式（下一轮输入命中纠正语）+ 显式（前端 👍/👎）两条入口，
  走同一条链路：纠正 → 上一轮重评 → 撤销成功记录 → 记为失败 + 生成补丁；
  新指标「答案采纳率」暴露在 `GET /api/memory/stats`
  （详见 [14-架构评审与改造建议.md](./archive/14-架构评审与改造建议.md) §2.3）
- **技能质量台账已建** — 验收样例通过率 + 线上被纠正情况合账，
  低通过率的技能自动降级（不再被 planner 选中），数据变好自动恢复；
  `GET /api/skills/quality` 可查（同文档 §2.4）
- **真机基线已建立** — L1 意图开发集 38 条 100%、留出集 96.3%；画像抽取精确率 100%；
  基线按分布报（`--repeat`，取最差一遍做闸门）。**答案质量仍无基线**
- **用户可见可管理长期记忆** — 「记忆」面板:列出、分类、忘掉、
  显示正在注入的内容;按 `session_id` 与 `scope` 分层（本地单用户，无用户级隔离）
- **能读文档** — docx/xlsx/pptx/pdf/md/csv/html,返回带锚点的 markdown(锚点带页码/表名/单元格),
  可反查原文;扫描件 PDF 明确报错而不是返回空
- **意图只由 LLM 判** — 规则退到结构守卫（只判空输入）；
  实测规则+LLM 94.7% vs 只有 LLM 97.7%，用规则猜说法会拖低准确率
- **向量检索默认关闭** — 没配 `EMBEDDING_PROVIDER` 就只用 FTS + CJK 通道 + 常驻注入；
  这是刻意的：随机向量做语义检索比不检索更差（同文档 §2.2）
- **答案质量无基线** — 意图和画像有了,但回答得好不好仍需人工标注问答对；
  所有「质量」改动目前无法验证是变好还是变坏（同文档 §4.1）
- **C-02/03/04 未完成** — 配置诊断命令、Patch 审计 UI、文档随代码演进
- **M2~M4 未开始** — 见 [11-开发任务清单.md](./11-开发任务清单.md)
