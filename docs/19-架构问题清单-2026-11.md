## P0

### 01 · 同一个会话没有串行化，一轮对话的状态全挂在 Agent 实例上

> **状态：✅ 已修复**（2026-11-19）—— 见上方第二批进度表。

**证据**

- `backend/websocket_handler.py:189` 直接 `await session.agent.handle(user_input, batcher.send)`，没有锁、没有队列。
- `core/agent.py:618` 的 `handle()` 依赖一整套可变实例状态：
  `self.identity` / `self.execution_id` / `self.context` / `self._profile_cache` / `self._last_exec_ctx`，
  以及闭包里的 `pending_async`、contextvar 里的 emitter。
- 两个入口都能并发进入同一会话：
  1. 重连时 `client_id` 变新，`backend/session.py:114 get_or_create` 在旧 Session 尚未被 TTL 回收（`ttl_s=3600`）时**新建一个 Agent**，但 `session_id` 相同 → 两个 Agent 同时往 `sessions.db` 写、各自维护摘要基线。
  2. ~~`/api/teachings/*` 等端点直接对 `sessions.get()` 拿到的同一个 Agent 调方法~~
     —— **复核后不成立**：teachings 走独立的 `TeachingSessionStore`，不碰 Agent。

**影响**

trace 串台、纠正信号挂到错误轮次、滚动摘要的序号覆盖错乱。这类问题不会抛异常，只会让"记忆看起来有点怪"，最难排查。

**建议改法**

在 `Session` 上挂一个 `asyncio.Lock`（或长度为 1 的 `asyncio.Queue`），`handle` 前 `async with session.lock`；dispatcher 只负责"解析 + 投递"，不负责执行。同时把"同 session_id 重建 Agent"改成"复用仍存活的 Session，仅更新 client_id"。

**验收**：构造两个并发请求打同一 session，断言两次 `handle` 的执行区间不重叠（可用时间戳区间或打点断言），且 `session_messages` 的 `seq` 连续无重复。

**工作量**：0.5–1 天。**风险**：低（但需同时改 §02，否则排队会顶在 dispatcher 上）。

### 02 · dispatcher 是全局唯一订阅，慢轮次拖住所有连接

> **状态：✅ 已修复**（2026-11-19）—— 见上方第二批进度表。

**证据**：`backend/websocket_handler.py:260-262` 只注册了一条 `ALL_TOPICS` 订阅，chat 在回调里整轮 `await`。

**影响**：一次 60s 的回答期间，其他连接的 `init` / `ping` / `feedback` 全部排队；前端表现为"另一个标签页没反应""心跳超时重连"，进而触发 §01 的重连重建 Agent。

**建议改法**：dispatcher 降级为路由器——解析 topic/type 后投入 per-session worker（`dict[session_id, asyncio.Queue]`），`ping` / `init` 走独立快通道不排队。与 §01 的锁一起做，避免"两把锁互相等"。

**验收**：并发起 1 个长任务 + 10 个 `ping`，断言 `ping` 的 P99 延迟 < 100ms。

> **已知残留**：重连时若上一轮仍在跑，它的事件仍推给**旧的** `conn_id`，
> 新连接收不到（这一轮会"静默"）。后续可把推送目标改成 session 当前的
> `conn_id`（需要在 Session 上记 `active_conn_id`），本轮未做。

**工作量**：1 天（含 §01）。**风险**：中（生命周期与清理逻辑要跟着改）。

### 03 · ToolHub 没有参数校验边界，两派 `execute` 签名并存

> **状态：✅ 已修复**（2026-11-19）—— 见上方第一批进度表。

**证据**

- `tools/hub.py:336-342`：`return await execute(**params)`，`ToolSchema` / `ToolParam` 只用于给 LLM 看，执行前不校验。
- 工具实现分两派：`async def execute(self, **kwargs)`（`python_exec`、`file_read`、`document`…）**静默忽略拼错的参数**；强签名的工具直接 `TypeError`。

**影响**：LLM 把 `path` 写成 `file_path` 时，一半工具报"path 不能为空"，另一半"成功但什么都没干"——后者会被模型当成事实继续推理，产生看似合理的错误结论。

**建议改法**：在 `_call_instance` 之前加一层 `validate_and_coerce(schema, params)`：必填缺失报错、未知参数报错（或按白名单丢弃并记录）、基础类型转换（str/int/bool/list）。把 `**kwargs` 派工具逐步改成显式签名。

**验收**：新增参数矩阵测试——缺必填 / 多未知 / 类型错 / 正常，四种情况各断言明确的错误信息。

**工作量**：1 天。**风险**：低-中（未知参数改为报错可能让现存 skill 暴露问题，建议先 warn 一周再转 error）。
