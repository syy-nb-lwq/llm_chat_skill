## 「新对话」失效修复（reset 可见性）

用户问"重启后对话不刷新吗、怎么开新对话"，查下来发现 reset 是半残的：

- 重启不丢是**设计**：前端 localStorage 存 `client_id` + `session_id`，重连带
  session_id → 后端复用 Session → Agent 从 sessions.db 恢复最近 8 条；前端
  `loadHistory()` 拉 `/api/session/messages` 渲染。这套是 docs/13 的"短期记忆全量保留"。
- 但「新对话」（输入框右边 ↺）只做了本地清屏 + `mark_reset`，而前端恢复用的
  `/api/session/messages` **不按 `reset_at_seq` 过滤** → 点完刷新，旧对话全回来；
  更糟的是 Agent 侧是按 reset 点过滤的，于是**界面显示旧对话、模型已经忘了**。
  实测：reset 后 `get_messages` 18 条 / 过滤后 0 条。
- 修复：`short_term.messages()` 加 `from_seq`，接口传 `reset_at_seq`。
  **过滤必须在 SQL 里** —— 先 LIMIT 再 Python 筛，reset 前消息一多就把新消息
  挤出窗口，表现成"重置后新说的话也看不见"。测试用 limit=1 钉住这个坑。
- 管理员接口 `/api/sessions/{sid}/messages` 保持不过滤（看全量档案），docstring 写明两个口径。
- 前端 ↺ 的 title 改成"新对话（清空当前上下文，历史仍保留在库里）"。

另外：真实库里所有会话 `reset_at_seq` 都是 0，说明这个按钮此前从未成功用过。

踩坑：heredoc `cat >>` 因重试写了两遍测试函数，F811 才暴露；删 37 行恢复。
教训：追加到文件的操作失败重试后，要检查是否重复写入。
