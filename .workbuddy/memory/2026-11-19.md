# 2026-11-19

## 本地单用户化改造（多用户隔离剥离）

**背景**：项目实际是跑在使用者本地的单用户工具，之前却按多用户设计，积累了
一整套 `user_id` / 令牌 / 假用户服务 / 数据隔离机制。docs/17 里的 P0-1
（产物越权）、P0-2（执行串味）都建立在多用户并发的前提上。

**用户决策**：彻底删除 `user_id`（含 SQLite schema 与 SQL 过滤），
保留 F0–F3 多智能体地基、剥离其中的用户维度。

### 做了什么

| 层 | 改动 |
|---|---|
| 身份 | `core/identity.py` 四级标识 → 三级（去掉 `user_id`）；`core/agentkit/identity.py` 同步 |
| 执行隔离 | `core/exec_context.py`：`scope_key` 从 `user::session` 改为只用 `session_id`；**并发隔离保留** |
| 存储 | `core/memory_db.py` / `core/session_memory.py`：schema 删 `user_id`/`tenant_id` 列 + 迁移（`DROP COLUMN`）；检索 SQL 去掉 user 过滤 |
| 鉴权 | `infra/auth.py` 重写为只保留 `gen_session_id`/`gen_client_id` + no-op `require_auth`；删除 `core/user_service.py` |
| 后端 | `backend/session.py`（`ClientIdentity` 去 user/token）、`backend/websocket_handler.py`（去令牌校验）、`backend/main.py`（删 22 处 `@require_auth` 实际校验、`/api/users` 改单用户） |
| 工具 | `tools/proposal.py` / `hub.py` / `meta_tools.py`：`owner_user_id` → 只留 `owner_agent_id` |
| 前端 | `websocket.js` 去 token 收发；`config.js` owner token 变 no-op；`MemoryPanel`/`App.vue` 改用 `session_id` query |
| 记忆 | `core/memory_writer.py`、`core/semantic_memory.py`、`core/agentkit/memory.py`、`core/agentkit/sources.py`：去 `user_id` 参数，保留 scope/agent 分层 |

### 关键坑

1. **SQLite 删列**：用 `ALTER TABLE ... DROP COLUMN`（3.35+），但列上有索引时
   会失败 —— 必须先 `DROP INDEX`。`memory_db` / `session_memory` 都写了幂等迁移。
2. **`require_auth` 注入 `request` 参数**：保留注入但去掉 `annotation=Request`
   会让 FastAPI 把它当必填 query 参数 → **全部接口 422**。正确做法是直接
   `return func`（no-op）。
3. **批量正则替换的副作用**：`user_id=xxx` 的替换会误伤 `owner_user_id=xxx`
   → 变成 `owner_owner_agent_id`。涉及字段名时不能无脑正则。
4. **位置参数**：`append_message(sess, "u1", role, content)` 这种
   **位置传参**的 user_id，正则处理实参名抓不到，要单独按方法名处理。
